# Lumen — Product Principles

## Product proposition

Lumen is an evidence-driven academic planning assistant for parents. It helps decide what a child should learn, practise, revisit, or skip based on curriculum, schoolwork, goals, learning evidence, and available time.

The parent is the user. The child does not use the application directly.

## Core loop

1. Parent provides curriculum context, schoolwork, goals, and available time.
2. Lumen interprets the evidence and identifies what matters now.
3. Lumen recommends a focused plan within the parent-set time budget.
4. The child works outside the app using school material, paper, verbal practice, or targeted checks.
5. The parent brings results back into Lumen.
6. Lumen updates its view of the child's learning state.
7. The plan changes when the evidence changes.

## Core product idea

**Evidence → Decision → New Evidence → Changed Plan**

Lumen is not primarily a worksheet generator or an AI tutor. Its core value is deciding what is worth spending limited study time on next.

## Learning-state philosophy

For each concept, Lumen should reason about dimensions such as:

- Understanding
- Recall
- Application
- Retention
- Evidence
- Confidence

Unknown is a valid state. One mistake must not automatically become a diagnosis of weakness.

## Recommendation philosophy

Every recommendation should be explainable through:

**Recommendation → Evidence → Confidence → Uncertainty → Suggested verification**

When evidence is insufficient, Lumen should seek the smallest useful piece of new evidence rather than simply generating more practice.

## Time is a constraint

Available study time is set by the parent. Lumen decides how best to allocate that time. It must not silently invent or change the parent's time budget.

## Parent-only interaction

The app is designed for the parent. The child may complete work outside the application, and the parent records or uploads the result.

## UX principles

- Decision first, explanation second, evidence third.
- Keep the home screen focused on what to do next.
- Prefer concise, high-signal recommendations over methodology-heavy explanations.
- Use progressive disclosure for evidence and reasoning.
- Preserve uncertainty instead of overstating mastery.
- Score is evidence, not the conclusion.
- Avoid child-facing visual language and generic edtech patterns.
